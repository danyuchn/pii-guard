# /pii-terms

把 `$1` 這份名單交給 pii-guard：程式讀欄位、你確認每欄是什麼，之後這些值在所有
進模型的內容裡都會先被換成代號。

## 絕對禁止

- **不准 Read、cat、head、grep、open 這份名單檔案**，也不准用任何方式把它的內容
  讀進上下文。你只能看下面第 1 步的 `--json` 輸出，那份輸出刻意不含任何值。
- **不准把名單內容寫進回覆、摘要或檔案。**
- 使用者若要你「看一下名單裡有什麼」，回答：這份工具的設計就是不讓模型看到名單，
  要看請他自己開檔案。

## 步驟

### 1. 讀欄位（不含值）

```bash
uv run pii-guard-hookd terms inspect "$1" --json
```

輸出是欄位名、猜到的類型、筆數、風險筆數、形狀規則。沒有任何一筆資料值。
若回報 `SHEET_NOT_FOUND` 或檔案有多個工作表，先問使用者要用哪一個，再加
`--sheet <名稱>` 重跑。

### 2. 讓使用者確認每一欄

用 **AskUserQuestion** 把欄位列給使用者確認，選項用中文標籤：

- 姓名 / 公司／組織 / 手機 / 市話 / 電子郵件 / 身分證字號 / 統一編號 /
  地址 / 銀行帳號 / 車牌 / 訂單／案件編號 / 其他要遮的字 / 不要遮

規則：

- 預設值用 `guessed_type`，不要自己另外猜。
- `guessed_type` 是 `SKIP` 的欄位（金額、日期、備註）維持「不要遮」，並說明理由：
  短數字到處都會撞到，遮了會把正常內容也改掉。
- 某欄 `risky` 大於 0 時，告訴使用者「這欄有 N 筆太短，會自動略過」。
- 某欄有 `shape` 時，告訴使用者「這欄格式固定，名單以外的新編號也會一起遮」。

欄位多的時候分批問，一次不要超過四欄。

### 3. 寫入設定

把使用者的選擇組成 `--map`，類型用英文代號（`PERSON`、`TW_MOBILE`、`ORDER_ID`…）：

```bash
uv run pii-guard-hookd terms import "$1" --map "姓名=PERSON,手機=TW_MOBILE,金額=SKIP" --yes
```

有工作表就一併加上 `--sheet`。指令會存下「哪一欄是什麼」的描述檔
（`.pii-guard/sources.json`，裡面沒有值），並請常駐服務重新載入。

### 4. 回報

只轉述指令印出來的**筆數與類型**，例如「姓名 120 筆、手機 118 筆已設定完成」。
服務沒在跑時轉述「下次開 Claude Code 會自動載入」。

不要重述任何一筆值。不要猜名單裡有誰。
